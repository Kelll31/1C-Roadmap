# 🔐 Политика безопасности (Security Policy)

## Поддерживаемые версии

| Ветка / Версия | Поддержка безопасности |
|---|---|
| `main` (актуальная) | ✅ Активно поддерживается |
| Исторические коммиты | ❌ Не поддерживаются — используйте актуальную версию |

---

## 🚨 Как сообщить об уязвимости

> ⚠️ **Не создавайте публичный Issue** для сообщения об уязвимости безопасности. Это может подвергнуть риску других пользователей, которые опираются на материалы репозитория.

### Что считается уязвимостью в этом репозитории?

Несмотря на то что **1C-Roadmap** — это документационный проект (не программный продукт), существуют ситуации, требующие конфиденциального рассмотрения:

| Категория | Примеры |
|---|---|
| **Опасный совет по безопасности** | Пример кода, который намеренно или случайно обходит RLS, создаёт SQL-инъекцию, открывает backdoor |
| **Утечка конфиденциальных данных** | Реальные логины, пароли, API-ключи, коммерческий код предприятий, персональные данные в примерах |
| **Дезинформация по ИБ** | Критически ошибочное руководство по настройке PBKDF2, SSL, прав доступа, которое создаёт реальную угрозу |
| **Вредоносный контент** | Скрипты или ссылки, замаскированные под легитимные ресурсы |

### Процедура раскрытия

**Предпочтительный способ — GitHub Private Vulnerability Reporting:**

1. Перейдите на вкладку **Security** репозитория:
   `https://github.com/Kelll31/1C-Roadmap/security`
2. Нажмите **"Report a vulnerability"**
3. Заполните форму с описанием проблемы

**Альтернативный способ — прямое сообщение:**

Напишите администратору проекта через GitHub:
[@Kelll31](https://github.com/Kelll31) → **"Send a message"**

### Что включить в сообщение

```
**Тип уязвимости:**
[Опасный код / Утечка данных / Ошибочный совет по ИБ / Другое]

**Файл и строка:**
06_FAQ_and_Tips.md, раздел "Подводные камни", пункт 7

**Описание:**
Пример кода демонстрирует обход RLS через прямой запрос
к базовым таблицам СУБД, что может ввести в заблуждение...

**Потенциальное воздействие:**
Разработчик, следуя этому примеру, создаст дыру в безопасности
в продуктивной системе с сотнями пользователей.

**Предлагаемое исправление (если есть):**
Заменить пример на корректное использование RLS через механизм
ограничения прав на уровне записей 1С.
```

## ⏱️ Сроки реагирования

| Этап | Срок |
|---|---|
| Подтверждение получения | **72 часа** |
| Первичная оценка серьёзности | **7 рабочих дней** |
| Исправление и публикация | **14–30 дней** (зависит от сложности) |
| Публичное раскрытие (после исправления) | По согласованию с репортером |

Мы придерживаемся принципа **Coordinated Disclosure (CVD)** — публичное раскрытие происходит только после того, как исправление опубликовано в `main`.

## 🔒 Рекомендации по безопасности для 1С-разработчиков

Поскольку репозиторий является учебным руководством, мы считаем важным зафиксировать ключевые принципы безопасности, которым должны следовать 1С-разработчики на основе наших материалов.

### Хранение паролей и аутентификация

```
✅ PBKDF2-HMAC-SHA256 (платформа 8.3.26+)   — криптостойкий
✅ SHA-512 / SHA-256                          — приемлемо
❌ SHA-1                                      — УСТАРЕЛ, уязвим
❌ MD5                                        — УСТАРЕЛ, взломан
```

- Используйте **беспарольный вход по QR-коду** там, где это возможно
- Настройте **Idle Timeout** — принудительное завершение брошенных сессий
- Интегрируйте **ЕСИА v3.34** для государственных информационных систем

> ⚠️ Переход на PBKDF2 **необратим** — база данных больше не запустится на платформе ниже 8.3.26. Создавайте резервную копию перед тестированием.

### Разграничение прав доступа

- Всегда применяйте **RLS (Record Level Security)** для многопользовательских систем
- Принцип минимальных привилегий: роли должны предоставлять только необходимые права
- Регулярно проводите аудит прав через **Журнал регистрации** и технологический журнал
- Логируйте административные действия и изменения прав доступа

### Безопасность кода и данных

```bsl
// ✅ Безопасно: параметризованный запрос
Запрос.Текст = "ВЫБРАТЬ * ИЗ Справочник.Контрагенты ГДЕ ИНН = &ИНН";
Запрос.УстановитьПараметр("ИНН", ИНН);

// ❌ Опасно: конкатенация строк → SQL-подобная инъекция через язык запросов
Запрос.Текст = "ВЫБРАТЬ * ИЗ Справочник.Контрагенты ГДЕ ИНН = """ + ИНН + """";
```

- Никогда не строите текст запроса конкатенацией пользовательских данных
- Не храните пароли и API-ключи в коде конфигурации или расширений
- Используйте **Безопасное хранилище** (КлючЗначение) или переменные окружения сервера

### AI-инструменты и конфиденциальность

- **Категорически запрещено** передавать реальный коммерческий код предприятия в публичные LLM (ChatGPT, Claude, Gemini)
- Для анализа продуктивных баз используйте **локальные модели** (Ollama) или корпоративные аккаунты с NDA
- Перед использованием AI-сгенерированного кода в продуктиве — **обязательный Code Review**

### Безопасность инфраструктуры

- Все соединения между компонентами кластера 1С — только через **SSL/TLS**
- Регулярные **резервные копии** с проверкой восстановления
- Тестируйте обновления платформы на **копии** базы данных, никогда не на продуктиве
