## ⚡ Быстрый старт

```bash
# 1. Форкните репозиторий на GitHub (кнопка Fork)
# 2. Клонируйте свой форк
git clone https://github.com/ВАШ_ЛОГИН/1C-Roadmap.git
cd 1C-Roadmap

# 3. Создайте ветку для изменений
git checkout -b fix/timeline-certification-order
# или
git checkout -b feat/add-bsp-section

# 4. Внесите изменения, затем закоммитьте
git add .
git commit -m "fix: correct exam prerequisite order in 02_Timeline"

# 5. Запушьте ветку и откройте Pull Request
git push origin fix/timeline-certification-order
```

## 🎯 Что можно улучшить

Мы рады любому вкладу! Вот приоритетные области:

### 🔴 Высокий приоритет
- **Устаревшие данные** — изменились зарплатные вилки, требования рынка, законодательство (НДС, маркировка, МЧД)
- **Битые ссылки** — не открываются ссылки на ИТС, GitHub-проекты, YouTube-каналы
- **Фактические ошибки** — неверные утверждения о платформе, алгоритмах, механизмах 1С

### 🟡 Средний приоритет
- **Новые разделы** — темы, которых не хватает в существующих файлах (1С:ГРМ, 1С:КЭДО, ЕГАИС и др.)
- **Улучшение примеров BSL-кода** — более наглядные или корректные примеры
- **Расширение FAQ** — реальные вопросы, которые вы или ваши коллеги задавали при изучении

### 🟢 Приветствуется
- **Исправление опечаток и грамматики**
- **Улучшение структуры и читаемости** разделов
- **Добавление ссылок** на качественные официальные источники (ИТС, 1C:УЦ1, GitHub)
- **Перевод** на другие языки (EN, UK, BE) — создайте Issue, обсудим структуру

## 🐛 Как сообщить об ошибке

Прежде чем создавать Issue:
1. Убедитесь, что аналогичного Issue ещё нет (поиск по [Issues](https://github.com/Kelll31/1C-Roadmap/issues))
2. Убедитесь, что проблема воспроизводима или утверждение действительно ошибочно

### Шаблон Issue

При создании Issue выберите подходящий шаблон или используйте структуру:

```
**Тип:** [Ошибка / Устаревшая информация / Битая ссылка / Предложение]

**Файл и раздел:**
02_Timeline.md → Неделя 9-10

**Описание проблемы:**
Утверждается, что LIFO — актуальный метод партионного учёта.
На самом деле LIFO отменён ФСБУ 5/2019 (с 2021 года).

**Предлагаемое исправление:**
Убрать упоминание LIFO, оставить только FIFO как актуальный метод.

**Источник (если есть):**
https://normativ.kontur.ru/document?moduleId=1&documentId=381498
```

**Метки (Labels):**

| Метка | Значение |
|---|---|
| `bug` | Фактическая ошибка в содержании |
| `outdated` | Устаревшая информация |
| `broken-link` | Не работающая ссылка |
| `enhancement` | Предложение по улучшению |
| `good first issue` | Подходит для первого вклада |
| `help wanted` | Требуется помощь сообщества |

## 🔀 Как предложить изменение (Pull Request)

### Правила именования веток

```
fix/описание-исправления       # Исправление ошибки
feat/название-нового-раздела   # Новый раздел или тема
update/имя-файла-год           # Обновление данных (зарплаты, ссылки)
docs/улучшение-структуры       # Структурные улучшения
```

**Примеры хороших названий веток:**
- `fix/remove-lifo-reference-02-timeline`
- `feat/add-1c-kedo-section`
- `update/salary-ranges-2026`
- `docs/add-bsp-examples-to-faq`

### Правила коммитов

Используем формат [Conventional Commits](https://www.conventionalcommits.org/):

```
<тип>(<файл>): <краткое описание на русском или английском>

[необязательное тело]
```

**Типы:**
- `fix:` — исправление ошибки
- `feat:` — добавление нового раздела или контента
- `update:` — обновление существующей информации
- `docs:` — улучшение структуры, оформления
- `refactor:` — реструктуризация без изменения содержания
- `chore:` — служебные изменения (`.gitignore`, метаданные)

**Примеры:**
```
fix(02_Timeline): remove LIFO reference, abolished by FSBU 5/2019

update(03_Competencies): актуализировать зарплатные вилки Q1 2026

feat(06_FAQ): добавить FAQ по настройке Cursor IDE для BSL
```

### Чеклист PR

Перед отправкой Pull Request убедитесь:

- [ ] Ветка создана от актуальной `main` (сделан `git pull origin main`)
- [ ] Изменения касаются одной логической темы (не «всего понемногу»)
- [ ] Все утверждения подкреплены источниками (ИТС, официальный сайт 1С, GitHub)
- [ ] Ссылки проверены и открываются
- [ ] Примеры BSL-кода соответствуют стандартам (см. раздел ниже)
- [ ] Нет опечаток (рекомендуем LanguageTool или Яспеллер)
- [ ] Заголовки не содержат двоеточий в конце (нарушение Markdown)
- [ ] Навигационные ссылки `← →` между файлами не нарушены

### Описание PR

```markdown
## Что изменено
Краткое описание изменений (2–3 предложения).

## Зачем
Почему это важно? Какую проблему решает?

## Источники
- https://... (ИТС, официальный сайт и т.д.)

## Чеклист
- [x] Проверил ссылки
- [x] Код соответствует стандартам BSL
- [x] Нет лишних изменений
```

## 📝 Стандарты оформления контента

### Общие правила Markdown

| Правило | ✅ Правильно | ❌ Неправильно |
|---|---|---|
| Заголовки | `## Раздел` | `## Раздел:` (без двоеточия в конце) |
| Выделение | **жирный** для ключевых понятий | Капслок ДЛЯ ВЫДЕЛЕНИЯ |
| Списки | Единый стиль (тире `-` или `*`) | Смешанный стиль в одном блоке |
| Ссылки | `[текст](https://...)` | Голые URL без текста |
| Таблицы | Выравнивание по смыслу | Пустые строки внутри таблицы |
| Эмодзи | Умеренно, только в заголовках | В каждой строке текста |

### Требования к источникам

- **Обязательные источники** для технических утверждений:
  - [ИТС 1С](https://its.1c.ru) — стандарты разработки, документация
  - Официальный сайт [1c.ru](https://1c.ru), [v8.1c.ru](https://v8.1c.ru)
  - GitHub-репозитории проектов (Vanessa, BSL Language Server и др.)
- **Допустимые источники** для рыночных данных:
  - HH.ru, зарплатные обзоры «Хабр Карьера»
  - Статьи на Infostart с указанием автора и даты
- **Не принимаются** как источники: анонимные Telegram-сообщения, устаревшие (>2 лет) статьи без ссылок на актуализацию

### Язык и стиль

- Основной язык документов — **русский**
- Технические термины пишутся как в официальной документации 1С: `&НаСервере`, `ФоновыеЗадания`, `ТаблицаЗначений`
- BSL-идентификаторы (имена процедур, переменных) — в коде или `инлайн-коде`
- Избегайте: жаргона («1С-шник», «конфигурятор»), неопределённых утверждений («очень быстро», «многие разработчики»)
- Числа и данные — всегда с источником и годом: «зарплата 200 000 ₽ (HH.ru, Q1 2026)»

## 💻 Стандарты примеров BSL-кода

Все примеры кода в документации должны соответствовать [стандартам разработки 1С](https://its.1c.ru/db/v8std).

### Обязательные требования

```bsl
// ✅ Правильно: понятные имена, разделение контекста, комментарий
&НаСервереБезКонтекста
Функция ПолучитьОстатокНоменклатуры(СписокНоменклатуры) Экспорт
    // Получаем остатки одним запросом для всего списка
    Запрос = Новый Запрос;
    Запрос.Текст =
        "ВЫБРАТЬ
        |    Остатки.Номенклатура,
        |    Остатки.КоличествоОстаток
        |ИЗ
        |    РегистрНакопления.ТоварыНаСкладах.Остатки(,
        |        Номенклатура В (&СписокНоменклатуры)) КАК Остатки";
    Запрос.УстановитьПараметр("СписокНоменклатуры", СписокНоменклатуры);
    Возврат Запрос.Выполнить().Выгрузить();
КонецФункции
```

```bsl
// ❌ Неправильно: запрос в цикле, нет разделения контекста
Для Каждого Строка Из Таблица Цикл
    Запрос = Новый Запрос;
    Запрос.Текст = "ВЫБРАТЬ ...";  // выполняется N раз!
    ...
КонецЦикла;
```

### Контрольный список кода

- [ ] Правильное разделение контекста (`&НаКлиенте` / `&НаСервере` / `&НаСервереБезКонтекста`)
- [ ] Нет запросов в цикле
- [ ] Нет модальных вызовов (`Вопрос()`, `Предупреждение()`) — только асинхронные
- [ ] Управляемые блокировки (не автоматические) для транзакционного кода
- [ ] Имена переменных и процедур — информативные, на русском
- [ ] Код запроса — многострочный с выравниванием, не в одну строку
- [ ] Пример компилируется без ошибок (проверьте в Конфигураторе или EDT)

## 🔍 Процесс проверки и слияния

### Сроки

| Тип изменения | Ожидаемое время проверки |
|---|---|
| Исправление опечатки / битой ссылки | 1–3 рабочих дня |
| Фактическое исправление с источником | 3–7 рабочих дней |
| Новый раздел или крупное дополнение | 7–14 рабочих дней |

### Возможные решения

- ✅ **Принят** — изменение сливается в `main` без правок или с минимальными комментариями
- 💬 **Запрос правок** — ревьюер оставит комментарии; ответьте и обновите PR
- ❌ **Отклонён** — если изменение противоречит концепции проекта или дублирует существующий контент (с объяснением)

### После слияния

Ваше имя автоматически попадёт в историю коммитов. Значимые вклады будут отмечены в описании релиза.
